# 内容完整性

本文描述发行源码对正式正文、后台请求和上下文注入的处理。第三方插件和供应商服务端实现不在WRX控制范围内。

## 已修复的正文裁剪

| 路径 | 原行为 | 当前行为 |
| --- | --- | --- |
| 用户/角色画像后台 | 裁输入发言、正文、条目和关键词 | 完整输入输出；正常结束才保存；覆盖前留14天原件 |
| 四表写入 | 摘要1200字符、标签120字符、约定1000字符 | 完整保存 |
| 活动后台及原生写工具 | 标题60字符、活动4000字符、心情200字符 | 完整保存 |
| 活动请求 | 单条3000字符，累计超预算丢弃早期消息 | 时间窗口内完整发言；容量不足报错 |
| 每日日记请求 | 单条发言3000字符、活动1200字符、先取最近40活动再按日过滤 | 发言与当天活动全文；不按40条隐式过滤 |
| 技能草案请求/采用 | 单条2000字符、总量只留末60000字符、角色字段8000字符、输出4096/8000 token | 完整输入/字段，不设本地输出上限 |
| 文字检索工具 | 每个命中只返回400字符 | 返回命中正文全文 |
| 日记/活动向量文本 | 只用前900字符，召回也复用该短文本 | 使用完整正文；旧向量不会自动重建或自动产生费用 |
| 冷记忆召回注入 | 1400字符预算丢掉后续已命中条目 | 已通过topK/阈值的条目全部完整注入，返回元数据亦完整 |
| 热日记/活动注入 | 最近20条之后再按时间筛选 | 在完整记录中按时间及状态筛选 |
| 后台输出结束状态 | 非画像任务可能接受长度截止后恰好可解析的JSON | 原生max-tokens、独立端点length均抛错，拒绝将结果继续保存 |

## 保留的范围与展示限制

- 画像匹配宏按关键词选条目；完整画像宏发送全部条目。两者均不裁正文。
- 历史窗口、召回topK/相关度阈值、工具显式limit、后台任务日期/小时范围是选择范围，未改为无限全库注入。
- 大段四表总结和日记可以分段处理；前后片段均保留，不是只保留一段。模型总结属于内容提炼，不能用代码测试保证语义绝无遗漏。
- 列表卡片、抓包搜索命中附近、调试API、错误日志保留短预览；不作为正式正文覆盖或模型消息。
- HTTP请求体、抓包大小、即时日记格式校验等上限采取报错/拒绝，不返回截断成功结果。
- 原生DSH请求构造器中所查到的maxTokens是路由输出参数，不是画像字符串裁剪；模型本身仍有有限上下文及输出容量，WRX不能取消供应商物理限制。

## 验证与恢复边界

- 修复改变将来的写入和请求，不会找回已丢失原文。若旧版本已经裁剪资料，需要从可靠原文或备份恢复，不能自动猜补。
- 已有旧向量不会自动重建；需要按实际情况显式重建，不自动产生远端模型/向量费用。
- 验证使用隔离数据和本地模型替身：长正文落库、完整请求、长字段采用、向量文本及多条召回注入。实际供应商端仍需独立验收。
