# 预设编排使用说明

兼容性与抓包入口位于请求编排区域。OpenCode Go能力由兼容性页管理；抓包可启停、展开、搜索及导出，记录适配器输入。详见[宿主接入与抓包](../integrations/dsh/README.md)。

## 最简单的用法

### 在加法编排中添加【删除】条目

原有加法条目可以全部保持，点击“＋删除条目”选择方式、填写目标并保存。删除条目默认插到列表顶部，自身不发送给模型；无论放在加法之前或之后，都会统一作用于本轮编排。不存在就跳过，不绑定某份DSH Agent preset，不要求启用全文条目。

- 按DSH分块名称删除：精确匹配名称，例如harness:identity或deployment:persona-prefix，删除该分块所有同名实例。对全文、旧组合、独立来源及正文中的来源宏统一生效，不影响其他分块。
- 按精确原文删除：粘贴要删除的一句话或一段文字，例如`You are an AI agent powered by DeepSeek Harness.`。从本轮生成的提示词文本中删除全部匹配，区分大小写、空格与换行，不使用正则，不跨消息拼接匹配。不更改用户输入、历史、时间背景、工具结果、思考回放或API tools；若同样文字出现在多个提示词条目，会同时删除。多条原文规则按列表中的规则顺序执行。

删除规则与普通条目一样可以启停、拖动、复制、导入导出。在编排预览的trace中查看operation=delete、target、matches，0表示未命中。禁用删除条目可立即恢复原文（下一轮新输入生效）。目标不能为空；按名称删除没有宿主分块数据时明确告警，不猜测内容。

“DSH 原生提示词 · 查看原文与添加删除规则”面板展示最近请求的原文。勾选某个分块会在顶部生成对应【删除】条目，取消勾选则禁用对应规则。暂未出现的目标仍保留，可以跨不同Agent preset自动命中。

### 可选：保留全文，只减去删除规则命中的内容

点击“添加 DSH 全文条目”可保留所有原生提示词正文，再使用上面的删除条目做减法。例如只去掉persona身份中的一句话，用“精确原文”删除该句即可，不必删掉整块persona。

全文先按分块执行删除，再按原顺序用空行合并为一条消息，抓包中显示为dsh.full。删除规则独立于全文来源，可以先借全文查看原文、设置规则，再关闭全文，启用DSH预设正文/工具说明/技能说明，规则仍会作用于当前编排。

全文条目可以在条目列表拖动排序、设角色或关闭。启用时，原来的DSH预设正文、工具说明、技能说明及DSH独立提示词入口（包括正文中的宏）自动跳过，避免重新加入被剔除内容或重复发送。旧条目保留，关闭全文条目后恢复旧编排。

“补齐常用内容”不再自动添加工具目录条目。API tools 的 schema 已包含工具名称、用途描述和参数定义，native 调用无需再发送一份目录 message。工具使用指导仍按原生分块提供，不等于重复目录。旧预设手动保存的 dsh.tools 条目和宏保留兼容，可自行关闭或删除；本次不会改写私人预设或实际工具 schema。

删除规则保存于每份WRX预设的prompts条目，operation=delete、delete_mode=section/text、target为目标。此前的dsh_prompt.excluded仍兼容用于旧全文配置；新页面勾选生成删除条目。换用不同DSH Agent preset时，执行阶段使用该次请求实际提供的素材，新出现的分块默认保留，未命中规则直接跳过。新输入取快照，工具续轮/压缩重编不在中途改变底稿或规则。

“全文”精确指当前DSH assembly.sections中的非wrx:提示词分块，包含全局与当前Agent作用域已经合并的正文，并非Agent preset的YAML全文。时间等assembly.contexts、历史/原生技能目录等消息及API tools不包含在内，也不会被剔除。页面展示最近一次经过WRX的请求，未分会话选择；切换Agent preset后先发送一次新输入，再重新读取查看新底稿。未接收到分块时明确提示为空，不虚构内容。

1. 先复制现有预设，保留原版作备份。
2. 自己写的规则用“＋普通条目”；已有正文不用改成宏。
3. 动态内容从中文下拉菜单选择，点击“＋加入所选内容”。新条目会出现在末尾并自动定位。
4. 从上到下排列条目。深度与同深度排序已取消，旧预设中的这些字段只保留作数据兼容，不影响实际顺序。
5. 预览实际编排并检查缺失素材提示，点击“保存预设”。启用统一编排后，另点“保存编排设置”。下一轮新输入生效，工具续轮继续使用原快照。

## 内容来源和正文二选一

“这条发送什么”选择自动内容后，不需要再填写正文或插入同名宏。原正文保留在数据里，不参与发送。普通文字条目才使用正文，可插入“现在是 {{current_time}}”这样的动态变量。

旧标记可通过中文来源替换，也可选择“改为自己写正文”解除标记。明确选择的来源优先于旧标记，不再发生填了history却仍按旧Chat History发送的情况。

## 推荐排布

信息与画像有五个独立来源：用户信息（静态，称呼与常驻信息）、用户画像（动态·完整，全部有正文的画像条目）、用户画像（动态·匹配，仅关键词命中条目）、角色信息（静态，人设字段）、角色画像（动态·完整，自我认知与全部条目）。建议信息放前面，画像放历史后面。用户两种画像按需选一种；角色只有完整模式，匹配以后再做。动态表示新一轮读取最新资料，不等于自动筛选。

旧User Definitions和Character Definitions仍是组合。拆分时将其“这条发送什么”分别改成用户信息、角色信息，再添加两种动态画像。不要同时保留旧组合与拆分项。完整用户画像与“匹配的用户画像”（及包含它的动态记忆组合）有重叠；按需选择完整或匹配版本。

固定人设与规则 → DSH预设/工具/技能 → 热日记 → 历史对话 → 用户信息与画像 → 助手信息与画像 → 动态记忆与召回 → 本次用户输入。

这是可调整的建议，不是必须全部加入。自动内容为空时不会生成空消息；预览能查看缺失提示。当前输入即使没有独立条目也会自动保留。历史缺失或关闭则不发送过去的对话。工具续轮的调用与结果保持完整并追加在末尾。

| 旧名称 | 含义 | 建议 |

要在历史和当前输入之间放画像：把旧Chat History的来源选为“历史对话”，将画像移到它后面，再将“本次用户输入”置于最后。无需在正文写{{history}}，也不要添加第二个历史条目。

## 历史窗口与动态画像

本会话发生压缩后，历史条目发送压缩摘要及未被覆盖的后续消息，不再发送摘要覆盖的本会话原文。摘要按覆盖内容的结束时间参与跨会话排序，并受时间窗口筛选；不会显示在“运行背景”中。多次压缩只保留宿主当前有效摘要。次数模式不把摘要当一次真人输入，N>0附带有效摘要，N=0不发送摘要。chatlog仍保留原文供后台总结，其他会话照常筛选。

历史对话就是顶部历史窗口的结果。“最近N次”只取当前会话先前N个用户回合；“最近时长”和“固定起点”按时间筛选各会话。当前会话保留工具轨迹，其他会话只提供带时间和来源的对话文本。当前用户输入额外保留，不受历史窗口裁掉。

用户信息与画像、助手信息与画像读取当前保存的资料，并非固定写死的提示词。每轮新用户输入读取最新状态，同轮工具请求复用快照；是否自动更新画像取决于画像模块的配置和执行结果。它们可以各自独立作为一条消息排列。

“用户画像（动态·匹配）”实际由代码用当前及上一条用户输入进行不区分大小写的关键词包含匹配。条目任意非空关键词命中就发送，无关键词或未命中不发送；没有命中时整个来源为空。它不再附带称呼、常驻信息，不使用向量或模型语义判断。“用户画像（动态·完整）”则不筛关键词，发送全部有正文的条目，包括没有关键词的条目。

动态记忆旧组合保持兼容，仍包含静态用户信息、匹配画像、四表热记忆、外出与AI笔记。需要分别排列时，关闭动态记忆组合，再添加独立项；热日记和召回另行添加。

## 常用内容按钮

“补齐常用内容（DSH＋记忆）”只补八项建议来源，不代表所有内容必须发送。已有来源即使关闭也算存在，重复点击不会重复加入；检查对应勾选框即可。新增建议项在列表前部，可继续拖动。

DSH预设正文来自宿主选中模式，不是当前WRX列表的副本；工具说明、技能说明与运行背景来自宿主。宿主收到请求后可发现独立内容，重新读取页面更新目录。组合与其独立子项不要同时加入，以免重复。真正工具参数仍通过模型API发送。

## 预览与兼容

预览不发模型请求，使用未保存的编辑内容和测试历史；不等于拉取真实聊天历史，也不代表供应商最终请求。缺失素材查看预览警告。

部分供应商会将system消息合并到开头。列表顺序是插件输出顺序；若需要中间系统消息原位保留，可以使用页面的转user兼容选项，但指令优先级会变化。
## 对话温度

预设页的“对话生成参数”支持自定义 temperature（0–2，可输入小数）。勾选覆盖后填写数值，点击“保存预设”。关闭覆盖则恢复使用 DSH 的原设置；旧预设已有的温度不会自动启用。参数随预设复制、导入和导出保存，聊天与工作可分别使用两份预设，切换后需保存。

仅统一编排开启时覆盖主对话；不改后台记忆模型或子 Agent。同一轮工具续轮与压缩重编沿用快照，下一轮真人或定时输入才读取新值。它不自动判断聊天/工作内容。

宿主需更新请求边界补丁（generation-options-v1），仅更新页面不足以生效。当前 DSH 0.2.1-rc.5 的 pi-ai 适配器支持 temperature，但没有透传 frequency_penalty / presence_penalty，界面因此不提供无效输入。未知导入字段仍保留，不自动发送。

模型实际支持以供应商为准：[DeepSeek 思考模式文档](https://api-docs.deepseek.com/guides/thinking_mode/)说明思考模式忽略温度及上述惩罚参数。提高温度不保证消除模板化措辞，第三方代理内部行为需另行验证。


## 角色绑定与保存范围（2026-11-06升级）

- 角色卡片只切换管理对象，编辑器打开该角色实际绑定的WRX预设，不改变DSH当前聊天。
- WRX预设集中存储，每份最多绑定一个角色；复用请点击复制，保存新副本后到角色看板绑定。名称按原字符串完全相同判重，不折叠大小写或空格。
- 查看其他角色已绑定的预设时只读，提供复制和切换管理角色入口；服务端也拒绝越角色改名、删除或覆盖。
- “保存预设”保存正文、排序、删除规则、温度。浏览器只提交变更项及编辑基线；不同预设合并保存，同一项冲突提示重新读取。
- “保存当前角色的启用与历史设置”保存WRX启用、历史窗口、时间戳、时区和中间system处理。它与看板WRX开关是同一启用状态，不改变既有记忆采集职责。
- 看板“保存绑定”保存启用、宿主Agent Preset绑定及WRX预设引用。未绑定独占模板不能启用；此按钮不保存预设正文。
- 切换卡片或离开编辑器时提示未保存内容。工具续轮继续使用已有回合快照，新输入才重新取样。
- 动态角色画像仅保留tag/keywords/content及版本，稳定名字与人设只在角色信息；独立看法系统已删除。
